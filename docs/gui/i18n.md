# 国际化与运行时语言切换

界面支持英文与简体中文（`en` / `zh_CN`），使用 Qt Linguist：`tr()` 抽取为 `.ts`，再编译为
`.qm`，运行时安装 `QTranslator`。

## 文件与构建产物

| 位置 | 内容 | git |
|---|---|---|
| `src/kimix_gui/translations/kimix_gui_{en,zh_CN}.ts` | 可 diff 的 XML 源 | 提交 |
| `src/kimix_gui/translations/*.qm` | 运行时加载的编译 catalog | 提交 |
| `src/kimix_gui/translations/GLOSSARY.md` | 中文术语与写法约定 | 提交 |

`.ts`、`.qm` 与术语表统一放在 GUI package 的 `translations/` 目录。Hatch 选择整个 package 时会
把它们收入 wheel。不要用 hatchling build hook 现场生成：隔离构建环境只有 `hatchling`，为两个
小 catalog 强制安装整套 PySide6 会显著放大发行构建。提交 `.ts` 与对应 `.qm` 使 clean checkout
和 wheel 的翻译行为一致。
`.qm` 缺失时 `QTranslator.load()` 会返回 False，`tr()` 静默回退英文，因此 catalog 完整性由测试
直接守护。

```powershell
uv run python scripts/gui/build_translations.py                 # lupdate + lrelease
uv run python scripts/gui/build_translations.py --update-only   # 只抽串到 .ts
uv run python scripts/gui/build_translations.py --release-only  # 只编译 .ts -> .qm
```

新增、删除或修改任何 `tr()` 文案后必须重跑脚本，然后翻译 `.ts` 中新出现的
`type="unfinished"`。`tests/gui/test_i18n.py::test_no_translation_is_left_unfinished` 会把漏译变成失败；
否则运行时只会静默回退到英文。

`kimix_gui_en.ts` 不需要手写：脚本按 msgid 自动填充，英文“译文”就是 msgid。

### `fill_identical()` 的历史坑

`fill_identical()` 曾使用带 `re.DOTALL` 的 `<source>(?P<source>.*?)</source>`。遇到已完成条目时，
惰性组会回溯跨过 `</message>`，一直吃到下一条 `type="unfinished"`，把
`kimix_gui_en.ts` 写成非法 XML；`lrelease` 会报 `Opening and ending tag mismatch`。

旧绕法是“先删 en.ts 再跑脚本”。现在正则已改成逐 `<message>` 块处理，并用 `[^<]*` 约束，
增量更新是正确的，**不需要删除任何 `.ts`**。`tests/gui/test_build_translations.py` 守着这个行为。

## 翻译边界：纯层只给结构，Qt 层成句

纯层不能调用 `tr()`：它不 import PySide6，而 `tr()` 是 `QObject` 方法。
`rendering.py` / `transcript_layout.py` / `tool_display.py` / `session_index.py` 中的文案，要么以
`LocalizedText(msgid, named_arguments)` 进入 transcript AST，交给 `qt/labels.py` 翻译；要么返回
结构化值给 `qt/` 成句。模型、工具、SDK payload 等外部原文使用 `LiteralText`，绝不翻译。
不要为了翻译在纯层引入 QtCore。

### 单词：英文作为 msgid

纯层继续返回英文，例如 `transcript_layout.LABELS`、`tool_display._FAMILY_LABEL`、
`session_index.UNTITLED_TITLE`。`qt/labels.py` 用 `QT_TRANSLATE_NOOP` 声明这些 msgid，让 lupdate
能够抽取；渲染边界（`qt/paint.py:layout_record`、`qt/transcript.py:_copy_record`、
`qt/home_view.py`）调用 `translate_label()` 查译。

词表中不存在的词原样返回，例如 `Bash`、`Custom Mcp`；它们由 wire 工具名派生，不是界面文案。
这样纯层无需改动，纯层断言也保持结构化。

### 句子与区域格式：纯层算值，Qt 层措词

纯层返回 frozen dataclass：

- `session_index.relative_time()` → `RelativeTime(unit, count, moment)`；
- `session_index.file_size()` → `FileSize(value, unit)`；
- `rendering.status_values()` → `StatusValues`。
- transcript 应用文案 → `LocalizedText`；外部内容 → `LiteralText`。

措词分别在 `qt/home_view.py` / `qt/status_line.py` / `qt/labels.py`。`RecordLayout`、复制文本与
accessibility formatter 都接收同一个 translator，在消费 AST 时才解析 msgid 与命名参数。

### 纯层异常：结构化问题

`llm.LLMInspectionError` 携带 `LLMProblem(kind, path, reason)`，Model 与 resolved selection 的
不可用状态也使用同一种 `LLMProblem`；`qt/settings_dialog.llm_problem_message()` 负责统一成句。
`LLMProblem.__str__` 故意保留英文，只供 traceback / 日志使用，界面逻辑不比较显示文本。

### 占位文案：纯层只表达“没有”

`transcript_layout.NO_DETAILS`（`"(no details)"`）是 msgid，不是直接屏幕文本。
`entry_summary()` 用空字符串表达 AST 没有摘要，`layout_entry()` 接收必填的 `placeholder=`，由
`qt/paint.py` 传入 `translate_no_details()`。是否缺少摘要由结构决定，不比较翻译前后的文字。

不要在 Qt 层比较占位符来判断是否有内容；该判断只能来自 AST 的空/非空结构。

### 结果行始终回退到可翻译 outcome

`tool_display._SDK_BORING_RESULT_MESSAGES` 中的 `success` / `ok` / `done` 等是 SDK 协议值，永不
翻译，只用来判断 message 是否没有信息量。`OUTCOME_SUCCEEDED` / `OUTCOME_FAILED` 才是屏幕文案。
`build_tool_result_content()` 无话可说时把 outcome 放进 `summary_parts`，因此不存在
`(no visible output)` 一类占位符。

那个旧常量既不在两本 `.ts` 中，中文界面会泄漏英文，信息量也比 `failed` 少。它还隐藏过一个
真实 bug：只有空白字符的 `message` 会让 headline 提前 `return ""`，跳过 outcome 分支，于是
失败工具行被渲染为 `Tool` + `(no visible output)`，完全丢失 failed。暴力遍历 10,976 组入参时
命中 432 次。`test_i18n_decoupling.py` 遍历空、空白、boring message × is_error，断言结果只能是
两个 outcome 之一，并断言源码不再出现那个字面量。

### 字段标签不参与程序判断

工具字段在 normalization boundary 已携带 role 与 hint；布局按这些枚举决定摘要、上下文和正文，
不再识别 `key:` 前缀或过滤元数据行。因此字段值即使包含冒号、换行或伪造标签也不会改变结构。
字段名目前保留 SDK/协议拼写以便诊断；若将来翻译，只需把 `ActivityField.name` 升级为 `TextRef`，
不需要同时修改任何过滤器。

## 文案规则

- 动态句子使用**命名占位符 + `str.format()`**，例如
  `self.tr("{shown} of {total}").format(shown=a, total=b)`。不要用 f-string 分块拼接；中英语序
  不同，拼出的句子无法整体翻译。译文中的 `{name}` 必须保留，可调整顺序，不能改名或漏掉，
  否则运行时会抛 `KeyError`。
- 不要使用 Qt 的 `%1` + `.arg()`。PySide6 的 `tr()` 返回 Python `str`，没有 `.arg()`；那是
  C++ / PyQt 写法。
- 不使用 `%n` 复数形式。单复数不同的句子写成两条完整文案，例如
  `"Delete 1 session?"` 与 `"Delete {count} sessions?"`。一是 `.qm` 缺失时 `"%n session(s)"` 会
  显示字面的 `(s)`，破坏“msgid 本身就是正确英文”的前提；二是 `fill_identical()` 只会移除
  `<numerusform type="unfinished"></numerusform>` 的属性，不会填入内容，英文包会得到空译文。
  中文只有一种复数形式，`%n` 在本项目没有收益。
- lupdate 能看到 lambda 中的 `self.tr("字面量")`，context 仍属于外层类名。因此
  `self._i18n.bind(lambda: x.setText(self.tr("…")))` 不需要 `QT_TRANSLATE_NOOP` 加显式查表。
  转换后运行一次构建脚本，对照 msgid 数即可确认。
- `qt/` 中不要使用 `#:` 开头的普通内部注释。lupdate 会把它当成显式译者备注，贴到后面遇到的
  第一个可译字符串上，即便相隔几十行且毫无关系。仓库没有文档生成器消费 `#:`，所以它只有这个
  副作用。`tests/gui/test_translation_quality.py` 要求 `qt/` 下没有 `#:`，两本 `.ts` 的
  `<extracomment>` 数为 0。将来确实需要译者提示时，紧贴对应字符串书写，并把守卫精确放开到那一条。
- 译法先查
  [`../../src/kimix_gui/translations/GLOSSARY.md`](../../src/kimix_gui/translations/GLOSSARY.md)。
  表里没有的术语，确定后补入；后续翻译沿用同一约定。
- 日期与时间使用 `QLocale`，不使用 `strftime`。`%b` 无论 UI 语言都只给英文月份。
  `QLocale` 语言取 `qt.i18n.active_language()`，不取 `QLocale.system()`；语言是持久化偏好，
  与系统 locale 只是偶然相同。图样（如 `MMM d`）本身也经过 `tr()`。
- 应用产生的 transcript headline 都用 `LocalizedText`，包括 compact、hook、approval 与历史提示；
  SDK 原始值和诊断字段内容保持 `LiteralText`。新增 msgid 要加入 `qt/labels.py` 的
  `TRANSCRIPT_MESSAGES`，再重建两本 catalog。
- 语言下拉的三个选项（`跟随系统 · System` / `English` / `中文`）不经过 `tr()`；每项用自己的
  语言书写，装了哪本语言包都能识别。定义在 `qt/preferences_dialog.py` 的
  `LANGUAGE_ENDONYMS` / `SYSTEM_LANGUAGE_LABEL`。
- 加载一律使用显式文件名（`qt/i18n.py:set_active_language`），绝不调用
  `QTranslator.load(QLocale.system(), ...)`。那个重载会遍历 `QLocale.system().uiLanguages()`，而
  Windows 上 `uiLanguages()` 不受 `LANG` / `LC_ALL` / `LANGUAGE` 影响；中文 Windows 永远以
  `zh-Hans-CN` 开头，会把测试全部带成中文。
- 默认偏好是 `auto`：`zh_*` → `zh_CN`，其余 → `en`。判定在纯层
  `i18n.resolve_language(preference, system_locale)`，Qt 侧传入 `QLocale.system().name()`。
  本期 `zh_TW` 也归入 `zh_CN`。
- 除应用自己的 `.qm` 外，还安装 PySide6 自带的 `qtbase_<lang>.qm`，用于 Qt 内置对话框按钮等。

## 运行时语言变化（`qt/retranslate.py`）

语言切换不重启应用：`apply_language` → `installTranslator` → Qt 把 `LanguageChange` post 给每个
QObject → 每个常驻控件的 `Retranslator` 子对象重跑其持有的文案语句。

转换范式是一行换一行，不编写 `retranslateUi()`：

```python
# 之前
title.setText(self.tr("Sessions"))

# 之后
self._i18n.bind(lambda: title.setText(self.tr("Sessions")))
```

`bind()` 会立刻执行一次，所以初始文案与转换前逐字节相同；之后每次 `LanguageChange` 都重跑。
手写 `retranslateUi()` 会让每条文案存在两份必须一致的清单，一旦漂移，唯一症状是某个 label
静默停留在旧语言。`Retranslator` 只保留一份清单。

### 已实测的 Qt 事实

以下行为钉在 `tests/gui/test_retranslate.py`（PySide6 6.11）：

| 事实 | 后果 |
| --- | --- |
| `LanguageChange` 到达 widget 下每个 `QObject`，包括深层 label 下的普通 QObject | `Retranslator` 可作为普通 `QObject` 子对象，宿主不必 override `changeEvent` |
| 无父 QObject 收不到该事件 | parent 到宿主就是订阅动作；没有 parent 会静默失效 |
| 事件是 posted，不是 sent | 测试在 `set_active_language` 后必须 `app.processEvents()`，与 `setFont` 同类 |

### 动态文案绑定重算方法，不逐次 bind

动态文案应绑定已经存在的重算方法，由它从当时状态重新推导。在刷新函数中再次 `bind` 会让 binding
无限增长，症状却不可见：文案一直正确，只是清单越来越长。`tests/gui/test_retranslate.py` 有守卫。

因此“事件到达时成句 + 存句子”被改为“存状态 + 派生句子”：

| 位置 | 之前 | 之后 |
| --- | --- | --- |
| `ChatView` 状态行 | `self._session_label = self.tr("session {id}")…` | `_session_state: SessionState` + `_session_label()` / `_refresh_status()` |
| `ChatView` 历史标签 | 文案与按钮启用混在 `_update_history_toolbar` | `_refresh_history_copy()` 只管文案，不改启用状态 |
| `HomeView` 详情空态 | 4 个调用点各自成句 | `_load_error` / `_loaded` + `_refresh_details_copy()` 五分支 |
| `HomeView` 列表状态行 | `_render_sessions` 内联 | `_refresh_browser_copy()` |
| `TodoPanel` | 全部来自 snapshot | 直接 `bind(self._sync_header)` |
| `SessionRow` | 构造时成句 | `_refresh_copy()`，标题 Untitled、相对时间、文件大小都随语言变化 |

以下位置无需加 `Retranslator`：

- 模态对话框（preferences / settings / request）每次打开都新建，且 `_apply()` 会 `accept()`；
- `qt/bridge.py` 文案在 emit 时翻译；
- toast / 通知（`main_window.py`）在发出时翻译；
- 右键菜单（`transcript.py`）每次点击新建 `QMenu`；
- `setWindowTitle("Kimix")` 是品牌名，不进入 `tr()`。

`Transcript` 是唯一的例外形态：它把译好的记录标签（`TOOL` / `ERROR`）直接画进 viewport，
没有控件持有文案，因此它绑定的是“作废缓存 + 重绘”，不是赋值。Qt 不会因
`LanguageChange` 自动重绘。

`KeyValueList.set_labels()` 是组件的重新成句入口。组件接收已翻译文案，所以语言变化时同时更新
屏幕标签与 `accessibleName`；构造时两者是同一字符串，读屏念旧语言而屏幕显示新语言是同一个 bug，
只是更难发现。
